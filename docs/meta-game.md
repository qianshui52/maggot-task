# 元游戏数值契约

改价格、奖励、勋章条件，先改这份文档，再改 `Core/ToolCatalog.cs` 和 `Core/GameProgress.cs`，最后跑 `--selftest`。

## 奖励只跟阶段有关

工具不提供任何倍率。整个应用的激励就是"越早清越值钱"，一旦给进阶工具加金币加成，"卵 100、苍蝇 10"这个梯度立刻失效，数值也没法对账。进阶工具只改两件事：一次能清几只、出手间隔多久。

## 击杀奖励

| 阶段 | 奖励 | 说明 |
|:--|--:|:--|
| 卵 | 100 | |
| 蛆 | 50 | |
| 蛹 | 25 | 需求没给数字，按"越早越值钱"的单调性插值 |
| 苍蝇 | 10 | |
| 已完成 | 0 | 不重复结算 |

金币只有一条规则：任务真的完成了，就按它当时的阶段发钱。桌面点击击杀和任务列表里的「完成」按钮走同一套记账（先 `Engine.Complete` 成功，再 `RegisterKill`），奖励一样。差别只在击杀多了光标和特效。

1.3.2 之前列表完成只打卡不发钱，用户点完 6 个任务发现货币没动。那是把"亲手击杀"和"完成任务"当成两件事了，已经统一。

有个坑要记住：阶段必须在 `Complete` 之前取。完成之后 `Status = Done`，`StageOf` 只会返回 `Dead`，奖励是 0。

## 连胜

活跃日指当天击杀大于 0，或者完成任务大于 0。

同一天杀多少只都只记一天。昨天活跃、今天还没动，连胜仍然有效，因为还没到判定时刻。跳过一整天就清零，`BestStreak` 保留。系统时间被往回调（gap ≤ 0）时不清零，否则改一下时间记录就毁了。

热度只是展示，不参与计算：

| 连胜 | 0 | 1–2 | 3–6 | 7–13 | 14–29 | ≥30 |
|:--|:--:|:--:|:--:|:--:|:--:|:--:|
| 等级 | 0 | 1 | 2 | 3 | 4 | 5 |
| 文案 | 熄灭 | 余温 | 小火 | 旺火 | 烈焰 | 燎原 |

## 落盘

`state.json` 升到 v4，多了一个 `progress` 节点：

```json
"progress": {
  "coins": 0,
  "totalCoinsEarned": 0,
  "totalSpent": 0,
  "totalKills": 0,
  "killsEgg": 0, "killsLarva": 0, "killsPupa": 0, "killsFly": 0,
  "tasksCompleted": 0,
  "currentStreak": 0, "bestStreak": 0,
  "lastActiveDate": "2026-10-26",
  "days": { "2026-10-26": { "kills": 3, "completed": 3, "coins": 300,
                           "egg": 1, "larva": 1, "pupa": 0, "fly": 1 } },
  "ownedTools": ["swatter", "spray"],
  "equippedTool": "spray",
  "unlockedMedals": { "first-swat": "2026-10-26" }
}
```

v1 到 v3 的存档没有 `progress`，加载时补一个空对象，不抛异常。`days` 只留最近 400 天。

清空任务不清钱包和勋章。那是长期进度，否则"清空"就成了把花掉的钱再赚一遍的漏洞。

## 一次击杀发生了什么

```
鼠标移动 → 驻留 0.18s → 悬停名牌（名字、阶段、+奖励）
                       └ 驻留 3.0s → 详情气泡（规格 §14）

点击 → 按工具形状判定 → 移除生物 → 消除特效（光环、光尘、+N）
     └ 引擎 Complete → 成功才发钱 → 连胜 / 日历 / 勋章 → 落盘
```

顺序是刻意的：先让引擎真完成任务，再发货币。引擎拒绝（任务已不存在或已完成）时这一只不产生货币，所以点空刷不出钱。

### 穿透和"悬停即武器"

穿透（`WS_EX_TRANSPARENT`）开着时，窗口不参与命中测试，收不到鼠标事件，光标也轮不到我们设置。所以"悬停变苍蝇拍"和"点击拍死"都不成立。让用户先去面板关掉穿透又太隐蔽。

现在的做法是每帧检查光标有没有压在虫子上（半径 1.7 倍），压上就临时撤掉穿透、换成工具光标，离开时（2.2 倍）恢复。面板上那个开关只表示"是否允许自动接管"。

两档半径是必须的。单档会让光标停在判定边缘时一帧接管一帧放行，光标形状和点击归属一起抖。

### 两个命中相关的坑

1. 分层窗口按 alpha 做逐像素命中。`AllowsTransparency=True` 的覆盖层如果背景是 `Transparent`（alpha 为 0），Windows 会当成"这里没有窗口"，点击直接漏给桌面，只有正好落在虫子实心像素上才收得到。用户的感觉就是"点旁边的空白完全没反应"。解法是 `RootCanvas.Background="#01000000"`，alpha 1/255，肉眼看不出来，但整屏可命中。

2. 蛆的 `Position` 是头部不是重心。绘制时从 `Position` 沿朝向反方向延伸约 0.95 倍 Size，判定圆心要是留在头部，用户按视觉重心点身体中段就会偏出半径。解法是 `CreatureVisual.HitCenter` 对蛆沿朝向后移 0.42 倍 Size，悬停和点击共用它。

## 验收

```bash
MaggotTask.exe --selftest                      # 607 项，其中元游戏 33 项
MaggotTask.exe --diag-game                     # 数值快照 + 并排打开军械库、荣誉殿堂
MaggotTask.exe --diag-kill --stage=larva       # 钉一只蛆在 (500,430)，供脚本点
MaggotTask.exe --diag-list                     # 连点 6 个完成，检查货币有没有涨
```

`--diag-kill` 正常情况下输出：

```
[diag-kill] 模拟悬停 @(500,430)
  面板穿透意图=True  自动接管=True  实际穿透=False  Win32穿透=False
[MaggotTask] 出手：命中 1 只，+10 货币，余额 70
```

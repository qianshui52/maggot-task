# 🪰 蛆虫任务 · Maggot Task

> 一个专治拖延症的猎奇桌面工具。
> 任务烂尾？它会变成苍蝇，在你的屏幕上交配、产卵、无限繁殖。

普通待办清单治不了拖延症，因为它**太安静了**。
蛆虫任务把任务的生命周期映射成昆虫的变态发育 —— 你不管它，它就在你眼前烂给你看。

**Android 版 + Windows 版双端交付，共享同一套生命周期引擎与视觉语言。**

---

## 📖 核心机制

### 一个任务 = 一只虫子

形态**完全由腐烂度 `rot` 决定**，不是由日历决定。`rot` 在 `[0, 1.20]` 之间连续增长。

| 阶段 | 触发条件 | 视觉表现 |
|:--|:--|:--|
| 🥚 **卵** | `rot < 0.18` 且未开始 | 白色小点，轻微呼吸感；越烂斑点越多 |
| 🐛 **蛆** | `rot ≥ 0.18` **或** 标记"开始写了" | 米黄分节，正弦蠕动，缓慢朝前拱 |
| 🟤 **蛹** | `rot ≥ 0.50` | 棕色胶囊，静止，每几秒抽动一下 |
| 🪰 **苍蝇** | `rot ≥ 0.78` | 深色躯干 + 虹彩翅，乱飞、急冲 |
| 💀 **拍死** | 标记完成 | 爆浆粒子四散，计入战果 |

**关键推论**：新建后从不碰，卵会**自己孵化**成蛆 → 蛹 → 苍蝇。
放着不管一定会烂 —— 这是整个产品的立论基础。

### 失控繁殖（签名特性）

- **两只以上**苍蝇才会交配。只剩一只时它只能干飞 —— 这本身就是"赶紧处理一只"的动机。
- 交配产下的卵带 `generation` 与 `gene` 系数：**每一代腐烂速度快 10%**，一代比一代凶。
- 苍蝇越多，产卵间隔越短（`interval = breedSeconds / (1 + (n-2) × 0.06)`）。
- `maxTasks` / `maxFlies` 是硬性安全阀，防止把设备拖死。

### 你躲不掉

关掉应用也会继续烂 —— 重新打开时按离开时长补算腐烂，
但**最多补 45 分钟**。足够肉痛，不至于隔夜回来满屏苍蝇。

### 软性冷却，不是硬性阻止

「我去做了」永远点得动，但连续狂点收益递减到 35%。
任何时候都有反馈，但刷不出效果。

### 每日任务（v1.1）

一个「每日任务」不是一个任务，而是一个**模板**。它每天生成一个新实例，
标题带当天日期，然后**完全按普通任务的生命周期腐烂**。

```
模板：「锻炼」
   ↓ 每天
锻炼 · 09-13   ← 今天，rot 从 0 开始烂
锻炼 · 09-12   ← 昨天没做完，它还在烂，甚至已经是苍蝇了
```

**漏掉的每日任务不会自动消失。** 这是刻意的 —— 如果它会自动过期，
每日任务就退化成了一个安静的清单，「昨天没做」这件事也就没有代价了。
未完成的旧实例会一直打上 **「已逾期 N 天」** 标记提醒你（由 `maxTasks` 兜底防堆积）。

- 新建模板 → **立刻**生成今天的实例（点完就能看见虫子出现）
- 停用模板 → 不再生成新的，**已有实例不受影响**（删虫子要有明确动作）
- 删除模板 → **已有实例保留**，退化成普通任务继续烂

### 每周任务（v1.2）

和每日任务**完全同构**，只是周期换成「周」，并且可以指定**星期几**生成。

```
模板：「写周报」  生成日：周五
   ↓ 每周五
写周报 · W37   ← 本周，rot 从 0 开始烂
写周报 · W36   ← 上周没写，它还在烂，甚至已经是苍蝇了
```

- **迟到也补**：设成周一、但周三才打开电脑 —— 周三照样生成，不会跳过这一周。
- 标题带 **ISO 周号**（`W37`），跨年那一周用 ISO 周基准年，不会算错。
- 漏掉的那一周同样**不会自动消失**，打 **「已逾期 N 周」** 标记。
- 点模板上的星期胶囊就能循环切换生成日，不用开下拉框。

### 音效（v1.1）

四种音效全部**程序化合成**，零音频资源文件（和生物绘制同一个原则）：

| 事件 | 听感 |
|:--|:--|
| 拍死 | 噪声爆裂 + 下行扫频，黏糊的爆浆 |
| 变苍蝇 | 低频锯齿 + 双层颤音，翅膀在耳边嗡嗡 |
| 孵化 | 极短的低频「啵」，黏腻破壳 |
| 繁殖 | 两声快速上行短音 —— 「更多了」 |

**默认开启。** 开关打开时会立刻试听，让你马上知道是什么声音。

### 看清每只虫是谁（v1.1）

- **Windows**：鼠标在某只虫上**停留 3 秒** → 弹出气泡显示它对应的任务
  （标题 / 阶段 / 腐烂度 / 放置时长 / 每日逾期）。
  虫群层是点击穿透的、收不到鼠标消息，所以用的是**轮询 `GetCursorPos`**，
  而不是全局钩子 —— 不注入任何东西，也不会被杀软盯上。
- **Android**：没有悬停，等价交互是**长按 600ms**。短按仍然是「我去做了」。

### 两端一致性怎么保证的

`docs/lifecycle-spec.md` 是**唯一事实来源**：常量、公式、阶段判定顺序、繁殖规则全部写死在里面。
Android 用 Kotlin 实现，Windows 用 C# 实现，两边各有一份验收自测，都对照规格第 11 节。
改任何数值都必须同时改两侧 —— 这是刻意的约束，因为"两端行为不一样"会让产品失去可信度。

## 🎛️ 可调参数

| 参数 | 默认 | 说明 |
|:--|:--|:--|
| `rotSpeed` | 1.0 | 腐化倍速，0.25–8.0（面板上是**对数刻度**滑块） |
| `baseRotMinutes` | 90 | 倍速 1.0 时，从 0 烂到 1.0 所需分钟数 |
| `breedEnabled` | 开 | 是否允许苍蝇繁殖 |
| `breedSeconds` | 40 | 交配间隔基准（受倍速影响） |
| `maxFlies` | 60 | **只封顶繁殖**：到达上限后不再产卵 |
| `maxTasks` | 150 | 任务总数上限（同样只封顶繁殖） |
| `clickThrough` | 开 | 虫群层是否穿透鼠标/触摸 |
| `notifyOnFly` | 开 | 烂尾是否推送通知 |
| `soundEnabled` | **开** | 4 种程序化合成音效（爆浆 / 嗡鸣 / 孵化 / 繁殖） |
| `dailyEnabled` | 开 | 每日任务总开关（关掉不影响已有实例） |
| `weeklyEnabled` | 开 | 每周任务总开关（同上） |

> ⚠️ `maxFlies` / `maxTasks` **绝不冻结腐烂**。
> 即使苍蝇已经触顶，正在腐烂的任务**仍然会正常变成苍蝇**，只是不再产生新卵。
> 否则任务会永久卡在「即将变苍蝇」，把产品最核心的承诺推翻。

> 想快速看效果：把腐化倍速拉到 `×8`，新建一个任务然后什么都别做。

## 🔍 调试技巧

- **想看清虫群**：关掉「穿透点击」。此时鼠标会落在虫群层上，
  **点一只虫子 = 对它的任务执行「我去做了」**（非破坏性，不会误删任务）。
  为避免你被自己困住，**45 秒后会自动恢复穿透**。
- **想验证繁殖**：把腐化倍速拉高，制造出 2 只以上苍蝇，然后等。
  面板上的「繁殖次数」与「血脉世代」会开始涨。
- **想验证每日任务**：在「每日任务」里加一个模板（如「锻炼」）→
  **立刻**会出现一只带今天日期的虫子。把系统日期往后调一天再打开应用，
  会再生成一只，而昨天那只**腐烂度不会被重置**。
- **想确认音效没坏**：把「音效」开关关掉再打开 —— 打开时会立刻试听「拍死」，
  听不到就是系统静音或音量合成器把本应用静音了。
- **冷启动不刷屏**：应用启动时不会逐条补发历史阶段通知，只发一条汇总。

### 虫群看不见怎么办（v1.2.3）

悬浮窗活在「另一个窗口层面」——它在不在、多大、有没有在画，应用里原本完全看不出来，
所以最常见的报障就是「统计里有 4 只蛆，屏幕上什么都没有」。
控制台上那张 **「虫群 · …」体检卡**就是为这件事存在的。
**判断只看一条原则：卡片上的「模拟 N」必须等于「引擎存活 N」。**

| 卡片显示 | 含义 | 下一步 |
|:--|:--|:--|
| 悬浮层正常 | 窗口已挂载、视口有效、时钟在跑、模拟里也确实有虫 | 若桌面上仍看不到，说明系统没合成这一层（部分 ROM 的省电/后台策略会这样），打开卡片上的开关 |
| 正常（当前没有任务） | 一切正常，只是没有活着的任务可画 | 加一个任务 |
| **同步异常：引擎里有虫，模拟里 0 只** | 引擎与模拟对不上号 | 这是 bug，请把卡片截图反馈 |
| 悬浮层未上桌 + 具体异常 | `WindowManager.addView` 被系统拒绝了 | 按下面「国产 ROM」那条去开权限；同时打开卡片上的开关 |
| 已挂载，但视口是 0 | 窗口存在但没被正确测量 | 服务会在 1.2 秒后自动改成显式像素尺寸重排一次 |
| 已挂载，但时钟没跑 | 渲染循环没启动 | 停掉再点一次「让虫群上桌」 |

卡片还会显示 **「动效 已关闭（生物静止）」**——那是系统开了「减少动态效果」
（开发者选项或省电模式）。它只会让生物静止，**不会让它们消失**。

> **v1.2.3 修掉的真机 bug**：`spawn`（入场缩放进度）原先只在 `step()` 里推进，
> 而 `step()` 在关闭动效时根本不会被调用 —— 于是 `spawn` 永远是 0，
> 而 `spawnEase(0)` 恰好等于 0，绘制层算出 `size = 0` 后直接 `return`，
> **整屏一只都不画**。体检卡当时只判断「窗口 + 视口 + 帧」这三样，于是报了
> 「悬浮层正常」，用户看到的就是那句最费解的话：「卡上说正常，但屏幕上什么都没有」。
> 现在 `spawn` / `age` 与动效开关**解耦**（关掉动效 = 不播入场动画，而不是不出场），
> 绘制层再加一道保险；体检卡的判断也纳入了「模拟里的生物数」。
>
> 同版本还修掉一个启动竞态：`bootstrap()` 原先是异步加载，于是悬浮服务可能
> 先于加载完成就起来 —— 那种情况下引擎里 0 个任务，Toast 会显示
> 「虫群已上桌 · 0 只」，屏幕上自然什么都没有。现在冷启动恢复是**同步**的。

卡片下方的 **「在应用内显示虫群」** 开关是**兜底方案**：开启后虫群会铺在任务控制台底下，
让「统计里有虫」终于能在屏幕上被看见。悬浮层挂载失败时它会**自动打开**，
而且**开关状态会被记住**，不必每次冷启动再翻一次。

（兜底层用的是它自己的一份模拟，和悬浮层那份分开：两层的可视区域不一样，
共用一份会让坐标系统互相打架。两层同时开着时位置会略有差异，这是有意为之。）

### 打开就闪退 / 黑屏怎么办（v1.2.4）

v1.2.4 起，应用**自带崩溃记录器**：任何未捕获的异常会把完整堆栈写到
`files/latest_crash.txt`，下次启动时**直接在屏幕上显示全文**
（纯系统控件渲染，不经过 Compose —— 崩溃若发生在组合阶段也能显示），
正文可长按复制。要点：

- **出现红色「上次运行崩溃了」页** → 长按选中正文 → 复制全文发出来，
  堆栈里的 `Caused by` 行能直接定位到文件和行号；
- **显示「上次启动没有走完」而没有堆栈** → 进程没有死于异常，而是被系统杀掉
  （省电策略 / 前台服务被限制），这要去电池优化设置里放行本应用；
- 同一份报告也落在 `Android/data/com.maggot.task/files/latest_crash.txt`，可随时取。

此外 v1.2.4 把**冷启动失败和悬浮服务失败都改成「降级而不闪退」**：
任务数据读不进来时控制台会显示原因并保留空列表（数据没丢，重开会再试）；
服务 `onCreate` 里的异常不再直接杀死整个进程。

> **v1.2.5 修掉的记录器自身 bug**：启动标记的读写顺序写反了——
> 先写「本次启动开始」再读「上次是否走完」，读到的永远是本次刚写入的状态。
> 症状是**每次冷启动都误报「上次启动没有走完」，且报告页上的
> 「清除并进入应用」点了没反应**（recreate 之后又回到同一页）。
> 现在读序已改正，死亡报告改为**一次性消费**：每份只弹一次，点了清除就能进应用。

---

> **v1.2.6 找到并修掉了从 1.2.1 以来「一点上桌就闪退」的原始真凶**：
> 悬浮窗里的 Compose 视图（`OverlayComposeView`）实现了一整套
> LifecycleOwner / SavedStateRegistryOwner，但**没把它们写进 ViewTree 的 tag**。
> Compose 建 recomposer 时只查 tag，不认「这个 View 自己就是 owner」——
> 于是挂载时抛 `ViewTreeLifecycleOwner not found`。这个异常是在
> Choreographer 的 traversal 回调里**异步**抛的，`addView` 外面的
> try/catch 根本接不住，主线程一炸整个进程就没了。
> 修复是把 owner 显式 `ViewTreeLifecycleOwner.set(this, this)` 进 tag。
> 这也解释了之前所有「统计里有虫、屏幕上没虫」的观测：窗口从未成功渲染过，
> 兜底开关（在应用内显示虫群）因此成了唯一能看到虫子的路径。

> **v1.2.7：悬浮窗「能活了」，但有三处体验缺陷，已修**：
>
> 1. **面板占满桌面**——内容原是固定 300dp 宽，在「显示尺寸=大」的机器上
>    （vivo 常见）300dp ≈ 85% 屏宽，加上内容本身高，看起来就是巨窗。
>    现在宽度 = min(280dp, 60% 屏宽)、高度封顶 68% 屏高，超高在面板内滚动。
>    标题行新增 **「收起」** 按钮；通知栏新增 **暂停/继续、显示面板、停止虫群**
>    三个动作（收起后的面板从通知找回，或再点一次「让虫群上桌」）。
>    隐藏面板改为**真摘除窗口**（原来 visibility=GONE 会留下一块看不见但挡触摸的区域）。
> 2. **桌面虫群不可见 + 体检卡报「视口 0×0」**——vivo 会把 MATCH_PARENT 悬浮窗
>    测量成 0×0，虫全被夹到一个像素点。虫群层现在**从创建起就用显式像素尺寸**，
>    不再依赖 1.2 秒后的自愈。
> 3. **「面板还在、服务已死」的灵异状态**——体检卡现在会写明原因
>    （「服务已停止（被系统回收或手动停止）」）；渲染循环的**单帧异常不再杀进程**
>    （记入非致命日志、跳过该帧）；窗口摘除失败也会留证据。

--- 

> **v1.2.8：桌面虫群成功，剩下「面板点不到 + 控制台太小」**：
>
> 1. **面板按钮点不到**——最大嫌疑是虫群层在某些 ROM 上被 `updateViewLayout`
>    重新压回 z 序顶端（且穿透关闭时它全屏可触摸），把发往面板的触摸全部吃掉。
>    现在每次动了虫群层（视口自愈、切换穿透）都把面板**重新顶回最上层**；
>    面板加 `FLAG_NOT_TOUCH_MODAL`（边界外的触摸放行）。
>    面板视图加了**触摸面包屑**：到达面板的前 6 次触摸会记入诊断日志——
>    下次体检卡上点「**复制诊断信息**」（新增按钮，把版本、体检数据、面包屑
>    一次性塞进剪贴板）再粘贴发来，就能看出事件死在哪一层。
> 2. **控制台「太小」**——每周任务的星期块从 34dp 放大到 44dp（弹性平铺一行）、
>    「添加」按钮 76dp → 96dp。

> **v1.2.9：点击诊断结果 + 自管 recomposer + 控制台可滚动**：
>
> 1. **诊断结论**——面包屑证明触摸已到达面板视图（DOWN/UP 干净配对、坐标正中
>    按钮），但点击处理器不执行；拖动（pointerInput）却正常。嫌疑集中在
>    lifecycle 感知 recomposer 的 PausableMonotonicFrameClock 在悬浮窗场景下
>    停摆。已改为**自管 recomposer**（自建 Choreographer 帧时钟 +
>    `setParentCompositionContext` 注入），完全绕开该路径。
> 2. **判定手段**——面板每个回调都写「面板点击:xxx」面包屑；标题行新增
>    **实时时钟**（秒在跳 = 重组活着）。下一份诊断直接分辨
>    「处理器没跑」vs「跑了但界面冻结」。
> 3. **控制台「完成任务栏被挤出去」的元凶**——主页面 Column **根本没加滚动**，
>    屏幕以下的任务列表/每日/每周区永远不可达。已补 `verticalScroll`。
> 4. 拖把手 4dp → 10dp 高、64dp 宽；拖动区覆盖整个标题栏。
>
> **Windows（v1.2.9 同步修复）**：腐烂时钟恢复**单驱动**——悬浮层可见时
> 10Hz 计时器只重置节拍器并让路，推进完全归 60fps 渲染帧回调；
> 隐藏/显示切换时重置节拍器防补算。SelfTest **527 通过 / 0 失败**。

> **v1.2.10：确认重组修复生效，控制台改单滚动面**：
>
> 1. 实机确认：面板**实时时钟在跳**（重组活了）、**按钮全部有反应**——
>    自管 recomposer 方案成立。
> 2. **控制台重构为单一滚动面**：1.2.9 的外层 verticalScroll 与内层
>    LazyColumn 嵌套打架，测量塌陷导致「每周任务」和底部按钮叠在一起。
>    现在标题/卡片/按钮/输入框/每日/每周/任务列表**全部是 LazyColumn 的
>    item**，一滚到底；「重置腐烂/清空全部」固定底部。输入框加了
>    `imePadding`，弹键盘时不被遮挡。

## ⚠️ 已知限制

- Android 悬浮窗在部分国产 ROM（MIUI / EMUI / ColorOS）上需要在系统设置里
  额外允许「后台弹出界面」和「自启动」，否则服务可能被杀。
- 前端服务通知在 Android 14+ 不可划掉，这是系统对前台服务的强制要求。
- Windows 版依赖 `AllowsTransparency`，在极少数开启强制 GPU 合成的环境下
  叠加层可能闪烁，此时关闭系统的"透明效果"即可。
- 生物绘制是**程序化矢量**，没有位图资源 —— 所以 APK 和安装包都很小，
  但也意味着画面上限由代码决定，不会出现手绘级的精细度。
- **漏掉的每日任务不会自动清理**：连续多天不做，实例会一直堆积、腐烂、变苍蝇。
  这是刻意的设计（漏掉就该有代价），由 `maxTasks` 兜底防止无限增长。
  不想要了就在列表里删掉，或停用/删除对应模板。
- Windows 面板标题栏按钮是 **52/74 × 32 px**：符合桌面指针的 32px 标准，
  但低于**移动端**的 44/48dp 触控标准 —— 这是按输入方式分别取值，不是疏漏
  （见 `docs/design-system.md` §7）。
